# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
`modelgate` (this package) and `MGS` (the spec it implements) version
independently — see `specs/mgs/MGS-1.0.md` §8. Each entry notes which
`spec_version` it targets, since that's what actually determines whether
two Reports are comparable, not the tool's own version number.

## [1.0.1] - 2026-07-27

Targets: **MGS 1.0**

### Fixed
- `Report.tool_version` was hardcoded to `"0.0.0.dev0"` in `__init__.py`,
  decoupled from the actual package version — every Report generated by
  the published `1.0.0` package incorrectly claimed to come from
  `0.0.0.dev0`. Now derived from installed package metadata
  (`importlib.metadata.version("modelgate-mgs")`), falling back to
  `0.0.0.dev0` only for an unbuilt editable checkout with no installed
  metadata. This directly undermines self-describing Reports (the
  citability goal in the README), so it's a correctness fix, not cosmetic.

## [1.0.0] - 2026-07-27

Targets: **MGS 1.0**

First production PyPI release, as `modelgate-mgs`. Package renamed
from the `modelgate` name used during development (see `0.1.0` below)
because production PyPI's `modelgate` is an unrelated project. No
functional changes from `0.1.0`.

## [0.1.0] - 2026-07-27

Targets: **MGS 1.0**

Development release, published to TestPyPI only, under the name
`modelgate` (not installable with a plain `pip install modelgate` —
production PyPI already has an unrelated package under that name).

### Added
- Initial `modelgate-core`: Reader → Manifest → Checker → Report pipeline.
- Readers: ZIP, plain directory (ImageFolder layout). Single shared
  structure-detection algorithm (single-root / flat-class / split) used
  by both — see `_readers/_structure.py`.
- Checkers for all four MGS 1.0 normative Requirements: MGS-0001
  (Structure), MGS-0002 (Integrity), MGS-0003 (Duplicate), MGS-0004
  (Balance). Resolution reported as an informative metric only (spec §5.5).
- `modelgate check <path> [--json] [--spec VERSION]` CLI.
- Conformance corpus (`conformance/`) and CI gate
  (`.github/workflows/conformance.yml`).

### Known limitations
- MGS-0001's "a label with zero samples" FAIL condition is not reachable
  in this implementation yet — `Manifest.labels` is derived only from
  samples that exist; detecting a genuinely empty class folder needs a
  Reader that also enumerates empty directories. See
  `specs/mgs/MGS-1.0.md` §9 and `checkers/structure.py`.
- Only ZIP and plain-directory Datasets are supported. COCO, YOLO, and
  HuggingFace-format readers are planned for a future minor release,
  once real usage signals which format matters most.
